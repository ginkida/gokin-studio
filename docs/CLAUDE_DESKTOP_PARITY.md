# Claude Desktop / Cowork capability boundary

Last verified: 2026-08-06.

Gokin Studio targets the local desktop workflow quality of Claude Desktop and
Cowork while intentionally limiting the model runtime to GLM and Kimi. It does
not claim that a local binary is Anthropic's cloud service.

| Capability | Gokin Studio | Boundary |
| --- | --- | --- |
| Multiple project workspaces and persistent chats | Implemented | Local project directories; durable sessions, forks, pins, drafts, recovery, search, exports, and validated last-workspace restoration. Official `Cmd/Ctrl+N` creates a session from any non-modal workspace focus, including an active editor; `Ctrl+T` remains a compatibility alias, and the in-flight guard coalesces possible native/WebView duplicate delivery. `Cmd/Ctrl+W` closes the selected chat through reversible archive semantics, refuses the project's last chat, and is suppressed during Quick Entry or any modal; duplicate native/WebView delivery is coalesced so one shortcut cannot close two tabs. Official `Ctrl+Tab` / `Ctrl+Shift+Tab` and `Cmd/Ctrl+Shift+[ ]` chords cycle sessions through one wraparound route, with physical-key fallbacks for non-Latin layouts; `Ctrl+PageUp/PageDown` remains a compatibility alias. Title-bar buttons, `Ctrl/Cmd+[ ]`, and dedicated Mouse Back/Forward buttons traverse one bounded project-local history across chats, Files, Artifacts, and Settings. Invalid/stale targets are skipped; a project switch resets the trail; auxiliary events cannot fall through to WebView document history or navigate behind approval modals/Quick Entry. The empty-chat welcome mounts only after a bounded session-and-directory-keyed language/Git snapshot, then uses fixed geometry and a stable scrollbar gutter so late metadata or font work cannot move the heading or composer |
| Arrangeable pane workspace | Implemented locally | Every chat owns a persisted recursive row/column split tree. Chat, Diff (including inline comments), Browser preview, Terminal, Files, Artifacts, Plan, scheduled Tasks, and Context can remain open together; dropping any pane on the left/right/top/bottom edge creates the matching split, accessible directional controls provide the same docking without a mouse, and mouse/keyboard separators resize either axis. Stable keyed pane hosts preserve live chat, terminal, and browser state while rearranging. A single capture-phase route owns the official Diff, Browser, Select element, and Ctrl-only Terminal chords before editors or nested menus, switches standalone Files/Artifacts/Settings back to the selected chat, and gives active modals exclusive keyboard ownership. Views restores closed panes, Cmd/Ctrl+\\ closes the focused non-chat pane and collapses its empty tree branch, and the global reset restores Chat + Context without deleting pane content. Legacy horizontal layouts migrate per session to the v2 tree |
| Integrated terminal tabs and folder routing | Implemented locally | The Terminal pane starts each PTY in the selected chat checkout, supports multiple independently live tabs, per-tab exit/error/restart/close state, and Arrow/Home/End/Delete keyboard navigation. `+` opens another root terminal; right-clicking a folder in Files or a directory-looking chat path opens a new tab at that exact session-relative directory. The backend re-resolves project/session/path at launch, rejects traversal, service metadata, files, special nodes, and every symlink component, and never falls back to another chat or the shared repository root |
| Local environment configuration | Implemented locally | Settings manages up to 64 global variables for new agent commands, background tasks, integrated terminals, and preview servers. Values are write-only across the UI bridge: only names return after save, while plaintext lives in a dedicated macOS Keychain item or a user-bound Windows DPAPI blob and is excluded from config, logs, exports, and backups. Save is atomic from the running app's perspective, malformed/unavailable storage fails closed, and isolation-owned names such as `HOME` and `PATH` are rejected, as is every name in the `DYLD_*`, `LD_*`, and `BASH_FUNC_*` loader/shell-injection families plus explicit entries like `BASH_ENV`. Existing processes retain their launch environment; repository `.claude/launch.json` values override matching global names for that preview and Studio retains control of fixed host/port/isolation variables |
| Parallel Git sessions with automatic worktree isolation | Implemented locally | The first chat in a newly connected Git project and every later chat/fork receive a durable managed checkout and branch. Agent tools, background tasks, terminal, `@file`, file picker, side chat context, Git state, and PR monitoring resolve against that session. `.worktreeinclude` copies only matching files that Git also marks ignored. Missing/tampered worktrees fail closed; dirty chats cannot be deleted or silently pruned, clean unused branches are removed, and branches with new commits are preserved |
| Visual change review with inline comments | Implemented locally | `Cmd/Ctrl+Shift+D`, the macOS View menu, command palette, session diff indicator, and review actions all route to the same persisted Diff pane toggle for the selected chat worktree; active modals retain keyboard ownership. The viewer is bounded file-by-file for staged, unstaged, untracked, renamed, deleted, and binary changes. Changed lines accept multiple keyboard-accessible comments; Enter records one comment and Cmd/Ctrl+Enter places the complete line-addressed feedback in the composer without auto-sending. **Review code** is an explicit user action that starts a read-only high-signal audit; GLM/Kimi must publish exactly one structured result through `submit_code_review`. Up to 20 findings are accepted only when their project/session, diff fingerprint, exact changed path, side, and visible line still match the backend-authoritative snapshot. Valid findings render inline by severity with an **Ask to fix** draft; an empty result is shown as a completed clean review, while changed diffs reject and clear stale findings. Large files/repositories are capped and visibly marked; external diff drivers and textconv are disabled. Git summary, plan progress, review, and commit all resolve against the same session checkout |
| Session file pane and spot editing | Implemented locally | Ordinary project-relative source/text paths clicked in chat markdown, changed-file summaries, Files, or Diff route to the selected chat's Files pane. Right-click on paths in Chat, Files, Diff, the editor, or artifact previews provides Attach as context, Open in a detected VS Code/Cursor/Zed, Show in Finder/Explorer, and Copy path. Every action re-resolves the selected chat checkout; executable choice comes from a fixed backend catalog and external apps launch only after a click. The bounded UTF-8 editor adds an `@path` draft without sending, supports native undo plus Cmd/Ctrl+S, preserves file mode, and writes a complete same-directory candidate before atomic replacement. SHA-256 content revisions detect edits made by the agent, terminal, formatter, or another editor and retain both sides behind explicit Discard/Override controls; Override is still bound to the newest displayed revision. Pane close, layout reset, and file navigation confirm unsaved loss, while accidental session switching retains a bounded in-memory draft for the current process. Traversal, case-insensitive `.git`/Studio metadata, symlink path components, binary/NUL, read-only, and files above 2 MiB fail closed |
| Agentic file, Git, shell, test, and web tools | Implemented | Same full registry for GLM and Kimi |
| Session permission modes | Implemented locally | The composer exposes Plan, Manual, Accept edits, Auto, and Skip through a keyboard-first menu (`Cmd/Ctrl+Shift+M`, arrows, Home/End, or numbered selection); matching `Shift+I/E` menus expose model and effort while the earlier model shortcut remains compatible. Plan is an ephemeral override for only the selected chat and snapshots atomically with the turn start; sibling chats keep the folder's durable execution default. In Plan the provider sees only a conservative read-only declaration allowlist, while runtime enforcement independently denies unknown/mutating calls without asking for approval. Shell/tests, write-capable Git, MCP, plugin agents, computer tools, memory mutations, repository plugin hooks, and model-driven plan lifecycle transitions are absent, so only the user-facing selector can authorize implementation. Manual asks before ordinary mutations and offers a persistent **Always allow** option only for an explicit allowlist of root-confined local file/document/Git tools. The folder-persisted **Accept edits** intermediate mode automatically permits only bounded project-local file/document edits and common dedicated filesystem operations; shell and Git-state mutations still re-enter review, while hard-gated variants are classified first. Scheduled runs can use the same policy. Each argument-free rule is scoped to one project, survives restart, appears with its scope in Context, and can be revoked there. Call-level classification runs before lookup, so document replacement, branch deletion, plugin force-ask, or missing sandbox still re-enter exact review. Shell, delete, network, connectors, SSH, browser/computer, schedules, PR writes, delegation, and unknown tools cannot be remembered. Auto additionally reviews bounded local Git operations deterministically, and Skip bypasses ordinary gates while destructive, desktop, SSH, PR-write, and external actions remain exact-reviewed |
| Artifacts and office documents | Implemented locally | HTML/SVG plus native DOCX/XLSX/PPTX/PDF generation, previews, versions, library, and reviewable Create/Update-with-agent flows. Files, library discovery, inline previews, snapshots, and atomic restore all resolve against the selected chat worktree; histories are isolated per session and removed with the chat |
| Live app preview, external Browser tabs, and dev servers | Implemented locally with explicit launch/domain/action review | The official `Cmd/Ctrl+Shift+B` chord and macOS View menu toggle a resizable Browser / Preview pane for the selected session worktree; `Cmd/Ctrl+Shift+P` remains a compatibility alias. `Cmd/Ctrl+Shift+S` or the crosshair starts in-frame element selection even while iframe focus is active: the token-bound bridge uses a CSP-nonced overlay, capture-phase suppression prevents the selected click from reaching the app, Escape cancels, and only capped selector/element/four-ancestor/rectangle metadata reaches a reviewable unsent draft; URL query/fragment data is removed. Studio reads Claude-compatible JSONC from `.claude/launch.json`, including `runtimeExecutable`/`runtimeArgs`, `program`/`args`, scoped `cwd`, bounded repo `env`, `port`, `autoPort`, loopback `url`, multiple configurations, and `autoVerify`; it also detects npm `dev`/`start` as a reviewable fallback. Commands run only after an exact in-app launch-summary review, with inherited provider credentials removed and `HOME`/cache/`HOST`/`PORT` kept isolated. URL-only configurations attach to an existing localhost server. HTML/PDF/image/video paths clicked in chat markdown/changed files, Files, or Diff open in this same pane from the exact chat worktree; static HTML keeps relative assets through a bounded read-only `os.Root` server protected by a unique origin, secret HttpOnly bootstrap, offline CSP, allowlists, and outward-symlink rejection. A private loopback proxy injects a nonce-bound bridge: `preview_browser` routes to the visible static file before a background dev server and returns bounded live DOM/runtime evidence plus a viewport PNG to the same model turn; it can click/fill/scroll/send constrained keys only inside that preview origin. **Persist sessions** is explicit opt-in per chat/configuration and restores bounded cookies/localStorage after server or app restarts; profiles are mode `0600`, never shared across chats, can be cleared in Preview, and are deleted with their chat/project. Successful file mutations invalidate old evidence and require another bounded inspect before completion. The same pane holds up to eight external HTTP(S) tabs per chat. Clicking a bounded credential-free HTTP(S) chat link now opens an explicit **Open in app / Default browser** destination chooser; Cmd-click on macOS or Ctrl-click elsewhere is the deliberate direct-system-browser shortcut. Invalid, control-bearing, credential-bearing, and oversized links are inert, the chooser is owned by the originating workspace and never stacks over another modal, and choosing the app still enters the existing exact-origin review. Address-bar navigation, cross-origin links, and redirects likewise re-enter review, and Allow once/Always allow never imply a subdomain or port. Each tab has a secret loopback hostname, ephemeral cookie jar, bounded traffic, and DNS-rebinding-resistant public-IP pinning. On macOS, first-party scripts run behind a runtime-installed `WKNavigationDelegate`: React may load a reviewed loopback frame, but child code remains confined to that exact local scheme/host/port; direct public/private navigation, `_top`, new windows, nested frames, refresh headers, and tampered resource URLs fail closed. Static cross-origin resource targets are HMAC-bound and dynamic cross-origin APIs remain blocked. Unsupported hosts automatically use a nonce-only script-disabled CSP. `external_browser` lists only safe tab metadata and can inspect or perform a bounded coordinate action in the backend-recorded active tab after a fresh exact-action review. Mutations require the exact URL from the latest inspection, and tab/session/token/origin ownership is checked again after approval; Kimi may receive the bounded PNG while GLM receives the sanitized DOM schema. Settings lists/revokes durable origins, which backups/imports intentionally omit. Private/local/reserved targets remain blocked. Unsupported protocols, cross-origin dynamic APIs, nested embeds, WebSockets/DRM, and pixel-perfect native capture remain gaps |
| Connector-backed live artifact refresh | Implemented with explicit local review | GLM/Kimi can refresh an artifact from project files and enabled MCP connectors; the task is placed in the composer and never auto-sent, while the artifact iframe itself receives no connector credentials |
| Connectors and MCP Apps | Implemented | stdio and remote HTTP/OAuth MCP, MCPB import, isolated MCP Apps host |
| Skills, plugins, commands, hooks, specialist agents | Implemented | Claude-compatible formats with digest review and normal permission gates |
| Computer use | Implemented locally | Explicit per-project opt-in, OS-observed foreground target, exact-action review; GLM uses Vision MCP for screenshots and Kimi K3 receives images natively |
| Scheduled tasks | Implemented locally | Runs while the desktop process is open; optional OS sleep inhibition can keep an awake computer ready. Deletion now matches the explicit desktop safety split: removing a task always stops its active scheduled runs and preserves their chats by default, while **Also delete run data from this device** separately removes only authoritatively linked child chats, transcripts, drafts, artifacts, preview profiles, and clean isolated worktrees. A backend preview reports bounded counts without transcript content or paths; stale/corrupt rows can remove only index metadata and never authorize chat deletion. The source chat is structurally protected, concurrent new runs force a fresh preflight, dirty/unavailable worktrees block the whole destructive mode before task metadata changes, and the model-facing schedule tool remains on the non-destructive default |
| Quick entry, voice, and screen drafts | Implemented locally | Independent opt-in controls match the macOS interaction model: double-tap Option opens a dedicated floating `NSPanel` with five recent chats without resizing the workspace, Caps Lock opens it and toggles dictation, and Option+Space/custom chords remain available. The panel moves the existing Wails WebView instead of creating a second backend, preserving drafts, approvals, and event ordering; unsupported hosts keep the geometry-restoring fallback. macOS 14+ dictation uses AVAudioEngine + Apple Speech.framework with separate Speech/Microphone permission status, partial/final transcript events, graceful finalization, immediate cancel, and WebView fallback elsewhere. Accessibility-gated shortcut monitors, atomic text/voice swaps, durable reviewable drafts, and one-click desktop/window capture handoff are covered; speech/screen input never auto-sends |
| Desktop links and background lifecycle | Implemented locally | Installed macOS/Windows builds register `gokin://studio/new`, project, and chat routes; single-instance IPC forwards links to the running process, while cold-start requests wait for React readiness. `q=` creates a bounded editable draft and never auto-sends. macOS close hides the workspace while keeping shortcuts and schedules alive. A real Quit on macOS/Windows/Linux snapshots running chats, queue workers/follow-ups, and side questions from backend-owned state before teardown. The native prompt contains counts only; Keep Running, sheet dismissal, duplicate Quit while the sheet is open, or dialog failure all prevent termination. Explicit Quit and idle Quit continue into the existing cancellation, resource cleanup, recovery-log, and atomic config-save path. Unsupported/duplicate/oversized links fail closed without logging prompt contents |
| Native desktop menus | Implemented on macOS | File, View, and Help expose new chat, reversible close chat, folder connection, workspace navigation, conversation/project search, command palette, sidebar, settings, shortcuts, and update checks with conventional Command-key accelerators. A fixed backend allowlist and bounded cold-start hand-off restore the existing window and reuse the same React actions; commands never navigate behind an approval modal |
| Transcript view modes | Implemented | Normal collapses consecutive tool/dispatch/reasoning activity into expandable summaries, Verbose shows every stored and live technical row, and Summary retains prompts, final replies, and changed-file summaries. The accessible composer menu, `Ctrl+O` on every platform, and macOS View menu use the same per-project persisted state; old quiet-mode settings migrate and search temporarily exposes hidden matches |
| Ephemeral side chat | Implemented locally | `Cmd/Ctrl+;`, `/btw`, the chat-header action, and the macOS View menu open a read-only drawer against a sanitized snapshot of the current session. It streams through an independently owned no-tools client, can run alongside the main agent, counts provider usage, and is discarded on close/session switch without adding its question or answer to the main transcript or history file |
| Work across local sessions | Implemented locally | The dedicated read-only `search_session_transcripts` tool searches case-insensitive literal text across other local chats, optionally narrowed to one exact project or explicitly including archived chats. It stays available in Plan mode, returns at most 20 recent bounded excerpts with a three-hit per-session and 8 MiB scan ceiling, labels them untrusted history, and excludes the caller, thinking, tool payloads, extracted document context, and attachment bytes. The session-routed `session_agent` lets GLM/Kimi list the 20 most recently active Studio chats except the caller, optionally include archived chats, read at most 40 recent visible transcript entries under a 48 KiB cap, send quoted source-attributed context, rename an ordinary target, and reversibly archive an idle target. Archive always requires exact-action approval in Manual, Auto, and Skip. Opaque project/session IDs are resolved exactly without default-session fallback. An idle target starts after its incoming card is published; a busy target uses the existing ordered follow-up queue. Current-session self-targeting fails closed, and unattended scheduled/plugin-agent runs cannot send or receive messages. For out-of-scope findings, the agent can offer a durable task chip; only a user click creates a fresh worktree-backed chat and starts its bounded prompt, while dismiss/start state survives reloads and forged RPC prompts fail closed |
| Pull request and CI monitoring | Implemented locally through GitHub CLI | A session-level bar polls the current branch PR on a fixed cadence and after turns/focus, reports bounded check state, and can notify on pass/fail transitions. One supplementary `gh pr list` query reconstructs up to 12 related PRs from a 100-record branch graph: nearest-to-farthest parents/ancestors, breadth-first children/descendants, then open siblings sharing the current base. Numbers, states, titles, and branches are bounded; URLs are reconstructed only from the validated origin and PR number. Invalid or unavailable supplementary data produces a local warning without hiding the authoritative current PR/CI snapshot, while background auto-archive and pre-mutation revalidation skip this extra query. Auto-fix is explicit opt-in with a three-fingerprint ceiling; squash auto-merge is separately confirmed and bound to the revalidated PR number and head OID. The empty-chat welcome never moves when late PR metadata arrives. A separate opt-in setting monitors eligible local sessions every minute in rotating batches of 20 while Studio is open and reversibly archives a clean, idle chat after its PR becomes merged or closed. Running or queued work, unattended sessions, dirty or unavailable worktrees, a dirty shared checkout, and the project's last active chat are retained. The event names the PR transition, the focused app shows a restore-oriented toast, and a background app uses the existing OS-notification path |
| Desktop release awareness | Implemented, notify-only | Studio checks the fixed GitHub Releases endpoint at most once per 24 hours (opt-out available), exposes an explicit **Check now** action, and shows a global release banner. Tags must be stable canonical semver and release links are constructed locally. Downloads and installs remain explicit until release artifacts are code-signed; published artifacts include SHA-256 checksums and the release workflow rejects a tag/version mismatch |
| Inter-project Dispatch | Implemented locally | Dispatches between connected project agents and retains the child transcript |
| Isolated code execution | Implemented with platform-specific guarantees | macOS Seatbelt and Linux bubblewrap are fail-closed; unsupported hosts are labelled honestly and exact-gated |
| Remote/cloud sessions | Not represented as local parity | Requires a multi-tenant execution service, short-lived cloud credentials, remote storage, and network egress proxy |
| Remote schedules while the computer is asleep/off | Not represented as local parity | Requires an always-on cloud scheduler and worker fleet |
| Mobile-to-desktop Dispatch | Not represented as local parity | Requires authenticated account sync, push transport, and a remote control plane |
| Hypervisor VM identical to Cowork | Not claimed | Studio exposes the real local isolation backend instead of labelling Seatbelt/bubblewrap as a VM |

## Model contract

The public config, RPC, health, pricing, scheduler, plugin-agent, and UI paths
accept only the catalog in `internal/studio/provider_catalog.go`.

- The bundled baseline catalog defaults to GLM 5.2: 1M context, 128K maximum
  output, text input, and native `reasoning_effort=high|max` with `max` as
  Studio's automatic choice.
- The bundled Kimi flagship is K3: `k3` for the Kimi Code Anthropic-compatible
  endpoint, up to 1,048,576 tokens, native image input, and
  `reasoning_effort=low|high|max` with `high` as the Coding automatic choice.
- A successful authenticated `/models` probe may add a newer GLM or Kimi
  numeric family to the picker without exposing any other provider family.
  Account-advertised models inherit conservative flagship limits until an
  explicit catalog ships, use the matching native effort UI/protocol, and
  expire from availability after 15 minutes or a credential change. Previously
  selected models remain runnable after restart.
- Unsupported or mismatched provider/model pairs are rejected before a client
  is constructed. Persisted legacy values migrate to the current safe default.
